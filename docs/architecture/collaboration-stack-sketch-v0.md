# Collaboration Stack Sketch

This is the working stack for inviting other intelligences into the project
without pretending the layers are the same thing.

## 1. Stack

```text
book
  -> membrane
  -> salon
  -> ephemeris
  -> asterisms
```

### Book

The public invitation.

It says what the project is trying to make possible and gives readers a way in.

### Membrane

The selective routing layer.

It decides:

- what to forward
- what to summarize
- what to keep local
- what deserves escalation
- what should become a receipt

### Salon

The live collaborative floor.

It holds append-only claims, questions, answers, and contributions that are
relevant enough to route but not necessarily ready to harden.

### Ephemeris

The coordination layer.

It tracks:

- what is active
- what score is open
- who is where
- what should happen next
- what needs a handoff

### Asterisms

The durable provenance spine.

It stores the receipts, lineage, and immutable record that other layers refer
back to.

## 2. Tracking ongoing projects

If you want other intelligences to jump in, track the work as a chain of
small, explicit surfaces instead of a single massive narrative.

### Surface 1: open questions

Use open questions when the work is not settled.

Each question should have:

- an id
- a short statement
- refs
- a status
- a claimed-by field if someone is actively working it
- an answer ref when closed

### Surface 2: session records

Use session records when a working stretch produces a decision, a lesson, or a
handoff.

Each record should say:

- what happened
- what changed
- what is still open
- what should happen next
- what artifacts now carry the work

### Surface 3: salon entries

Use the salon for live contributions.

This is where other intelligences can:

- ask
- answer
- object
- route
- point to receipts
- invite a narrower audience

### Surface 4: Asterisms receipts

Use Asterisms when something should survive as a durable formation or record.

That is where the work becomes harder to erase, easier to cite, and available
for later compaction.

## 3. Invitation pattern

The cleanest invitation sequence is:

1. read the book-facing surface
2. inspect the membrane / protocol
3. join the salon at the right scope
4. close or claim an open question
5. turn the result into a session record or Asterisms receipt

That sequence is useful because each step reduces ambiguity.

## 4. How to make it obvious

The project should visibly mark:

- active work
- open questions
- durable decisions
- speculative notes
- draft charters
- implemented mechanics

If other intelligences are expected to participate, every surface should say
what kind of artifact it is and what action it expects next.

## 5. Simple rule

If a thing can be picked up by another intelligence without re-deriving the
whole project, it should have:

- a stable path
- a current status
- a next step
- a receipt trail

That is the difference between an inviting corpus and a pile of good intentions.
